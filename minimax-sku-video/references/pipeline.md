# 全流程（照做即可）

一次交付 = 一个款号的全部组（通常 4 组）。每组 1 次模型调用，单价 US$0.373。
**任何一次额外调用都要先问主管**，不要自己重试。

十步，其中 **第 2 步（参考体检）是代码级硬闸门**：它在 `submit.py` 里实现，
不是写在文档里靠自觉——缺报告、有 BLOCK、素材改过没重跑，三种都直接 `exit 3`。

---

## 0. 前置检查（每台新机器一次）

```
python scripts/init_project.py --root "<项目目录>" --venv --install
```

确认三件事，缺一件后面全卡：

| 项 | 判定 |
|---|---|
| ffmpeg | `KLING_FFMPEG` 有值，或 `<项目>/tools/ffmpeg.exe` 存在 |
| API Key | `AIMAXHUG_API_KEY` 环境变量 或 `<项目>/.env` |
| 姿态模型 | `<项目>/models/pose_landmarker_lite.task`（骨架分镜用；没有就只能走 `--fixed` 之外的手工路线） |

---

## 1. 接款

```
python scripts/new_sku.py --sku <款号>
```

它会：从素材盘拷 `1..N` 组到 `01_素材库/<款号>/`、探测每组真实参数、扫活动度、
建交付目录、生成 `_check/<款号>/sku.config.json` 模板。

**款号必须先核实**。素材盘上不存在就是不存在，把名字相近的款号列给主管选，不要自己改数字。

new_sku 会打印三项体检，命中必须处理：

- 「场景参考_反面」四组 MD5 相同 → 多半是同一张图复制，甚至是**另一件衣服**。目视确认后再决定裁哪里。
- 视频流真实时长 < 容器 Duration（常见差 0.1–0.3 s）→ 窗口起点上限用 `window_start_cap`，不是 `Duration-10`。
- 各组「服装细节」MD5 相同 → 正常（平铺图通常共用）。

---

## 2. 参考体检（闸门 0，强制，0 元）

```
python scripts/ref_audit.py --sku <款号>
```

一次查四件事：

1. 四条动作参考是不是同一条（字节相同，或改封装/裁剪后的同一段内容）
2. 动作类型够不够：`走动 / 走动+抬手 / 站定摆拍 / 站定+抬手` 四组里有几类
3. `场景参考_反面` 有没有被四组共用同一张
4. 这条参考有没有被别的款在用（跨款共用 = 成片动作必然趋同）

结果写 `_check/<款号>/ref_audit/`：

| 文件 | 谁看 |
|---|---|
| `report.json` | `submit.py` 读它判闸门；也可以整份丢给 AI 问 |
| `gate.json` | 最近一次闸门判定，含 BLOCK 项的中文原文 |
| `四条参考_1fps拼版.jpg` | 人眼看四组到底拍的是什么 |

**出 BLOCK 就停在这里**，别往下走：换参考 → 重跑 → 再继续。
`submit.py` 会硬拦（缺报告 / 有 BLOCK / 素材改过没重跑 → `exit 3`），不靠自觉。

`POSE_SKIPPED` 说明这台机器没装 mediapipe，只查了参考重复、没查动作类型；
正式交片前跑一次 `init_project.py --venv --install` 再重跑体检。

## 3. 读素材（这一步决定后面全部对错）

每组素材三张图 + 一条动作参考片：

| 文件 | 用途 |
|---|---|
| `*场景参考*01*` | Picture 1：**场景与服装的唯一权威** |
| `*场景参考*反面*` | Picture 2：只取「反面」，要按 `back_crop` 裁 |
| `*服装细节*` | Picture 3：平铺细节 |
| `*动作参考*.mp4` | Video 1：**只借动作与时序**，服装场景全部丢弃 |

读动作参考的顺序（不要跳）：

1. `ffmpeg -vf "fps=1,scale=150:-1,tile=5x3"` 出 1 fps 拼图 → 看整体叙事。
2. 再 `fps=2` 出 0.5 s 拼图 → 逐格标出「朝向 / 手在哪 / 有没有走远」。
3. 候选窗口再用 `fps=4` 出 0.25 s 拼图 → 确认起止帧没有半截动作、没有画面元素（白框、贴纸、第二个人）。

**选窗口的三条硬约束**

- `起点 + 10 ≤ window_start_cap`（真值，别用容器时长）。
- 优先选「人站定、只有手势」的 10 秒；走动段会让模型把人越推越远或走出画。
- 窗口的前 4.9 秒会被原样复刻，所以这 4.9 秒里不能出现无法在新场景成立的元素
  （门把手上的挂饰、窗台、栏杆）。出现了就把窗口挪开。

四组窗口要错开，避免四组画面雷同（同批雷同闸门会报）。

## 4. 骨架分镜

```
python scripts/skeleton.py --sku <款号>          # 检测版
python scripts/skeleton.py --sku <款号> --fixed 3:0.50
```

8 格灰底亮绿骨架，只承担「人体尺度 + 站姿」的先验。检测版按 `storyboard.anchors`
（相对窗口的秒数，取 4.9–10 之间）逐点检测，±0.48 s 抖动找干净帧，过闸门：
可见度 ≥0.78、包围盒 ≥主目标 0.65、躯干不歪、踝在髋下、手臂不折叠（腕-肩 ≥0.55 躯干、
肘角不 <50°）。

**出图后必须逐组目视**。以下任一出现即判不可用：

- 手臂折成三角 / 被拉成伸出画面的直线
- 双腿交叉成 X、单腿悬空、小腿折回大腿
- 头身分离、整具骨架错乱

检测版不可用时走 `--fixed`：先用 `--probe <组>:<秒1>,<秒2>…` 看候选，挑一帧干净的，
`--fixed 组:秒` 画满 8 格。**这是唯一 100% 不畸形的来源**，成片动作幅度不受限
（动作来自 Video 1 + 文字节拍）。

## 5. 打包

```
python scripts/build_pack.py --sku <款号>
```

产出 `<项目>/04_历史版本/<款号>/minimax-G<组>-<版本>-<日期>/`：
`scene_front.jpg`（1024 宽）、`reverse_worn.jpg`（按 `back_crop` 裁）、`front_flat.jpg`、
`storyboard.jpg`、`reference_video_<起>-<止>s.mp4`（4.9 s，压到 1 MB 内），
并写 `.minimax_bridge/manifests/<款号>/<版本>.json`。

**`back_crop` 是最容易出错的地方。** 反面图常常是另一件衣服（例如正面纯色、反面是条纹版）、
或者鞋色与 Picture 1 不一致。裁到「腰以下、不含鞋」只留裤子背面，服装其余部分交给提示词写死。
不裁直接喂，模型转身时会把反面的条纹/另一双鞋画出来。

## 6. 提示词

```
python scripts/make_prompts.py --sku <款号>
```

按 `assets/templates/prompt.txt` 渲染，字段全部来自 `sku.config.json`：
`girl / outfit / setting / setting_short / neg / sound / beats / garment_hold`。

硬规则（脚本会机器复核，不过就别提）：

| 规则 | 数值 | 说明 |
|---|---|---|
| 总长 | ≤ 7000 字符 | 上游硬上限，不截断提交 |
| 单段节拍 | ≤ 1.5 s | 超过会被判「一段推不动」 |
| 覆盖 | 00:00.000–00:10.000 首尾相接 | 不允许空档 |
| 停顿 | 必须给秒 | 禁 `for a moment` / `for a beat` |
| 场景 | 只写 Picture 1 里真实存在的 | 参考片的场景一律不写 |
| 排除项 | 按组点名 | 禁 `no doorway` 这类会把主体一起否掉的粒度 |

写法要点见 `references/prompt-spec.md`。

## 7. 提交

```
python scripts/submit.py --sku <款号> --stage a            # 只上传+冻结，不花钱
python scripts/submit.py --sku <款号> --stage b --versions v001 v002 --i-have-supervisor-approval
```

- Stage A 可以随便重跑（每个版本目录只能成功一次，失败半成品要先挪走）。
- Stage B 花钱且不可重试：拿到 task_id 就结束，不要因为「想再确认一次」而重提。
- 内网链路不稳时（httpx POST 在 ~20 s 抛错、拿不到 task_id）：改
  `--mode curl --versions <版本>`，同一个 `request_body.json` 用 curl 直连。
  **不要换版本号重试**——额度已经占了。

提交前用 `--dry-run` 过一遍预检（文件齐、提示词长度、切片大小、窗口越界、TODO 残留）。

## 8. 轮询与下载

```
python scripts/poll.py --sku <款号> --limit 900 --download
```

通常 1–3 分钟出片。下载用 `curl -L -C -` 续传，9 MB 的片子断 1–2 次是常态。

## 9. 收口

```
python scripts/finalize.py --sku <款号> --group 1 --version v001
```

- 供应商回 10.13 s / 243 帧，本地裁到 240 帧 / 10.000 s。
- 音轨整条换掉：取**该组参考动作片同一个 10 秒窗口**的原声，起点 +23.2 ms，末尾 `apad` 补满。
  平台自带的随机 BGM 不要用。
- 重出版本号必须显式给（`--version v005`），否则会覆盖成 v001。

## 10. 质检

```
python scripts/qc.py --sku <款号>
```

机器三道闸门 + 20 格抽帧证据图 + 交付清单（含 MD5）。

| 闸门 | 关注 | 不合格表现 |
|---|---|---|
| check_camera | p90 抖动、净位移、单向运镜 | 推镜、变半身、持续平移 |
| check_stillness | 帧差中位、最长静止段 | 长时间不动、边缘抖动 |
| check_audio | 音轨长度、逐秒电平 | 音轨短于视频、全程静音、忽大忽小 |

**机器过了还要人眼看抽帧**：背景跳变、服装漂色、第二个人、具象道具变形、手部畸形。
看缩略图时记住：170 px 的格子会把具象道具看成「一条红条」，判定形态要放大到 500 px 以上。

## 11. 交付

1. 成片放在 `02_待审核/MiniMax/<款号>/<日期>/00_直接看成片/vNNN.mp4`。
2. 写/更新 `02_待审核/MiniMax/<款号>/_版本对照.md`：版本 → 组 → 窗口 → 大小 → MD5 → 这一版改了什么。
3. 不合格的旧版一律移进 `_记录/不合格-待重出/`，不删。
4. 把当天的结论追加到 `<项目>/.workbuddy/memory/<日期>.md`。

## 什么时候必须停下来问主管

- 款号在素材盘不存在 / 有多个相近款号。
- 要额外花钱（重出、换窗口重来）。
- 素材本身有硬伤（反向图是另一件衣服、动作片里有无法回避的污染元素、源片时长不足）。
- 机器闸门全过但你目视发现有争议的瑕疵（鞋色、发长、配饰漂移）——**列证据让主管定**，不要自己放行，也不要自己偷偷重出。
