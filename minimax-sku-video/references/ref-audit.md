# 参考体检（ref_audit.py）· 闸门 0

## 什么时候跑

- **十步流程的第 2 步，强制**：`new_sku.py` 把素材拷进 `01_素材库` 之后立刻跑，先确认这批料能不能用。
- **换过素材 / 补过参考片之后必须重跑**，否则 `submit.py` 会按「报告过期」拦下。
- 这是**代码级硬拦**，不是提醒：`submit.py` 在 Stage A / Stage B 之前先读报告，缺报告、有 BLOCK、报告过期，三种都 `exit 3`，连上传都不做。

原因：一次建单 US$0.373、失败不退。参考本身有问题时出片一定跑偏，而「不同款成片动作长得一样」的头号原因就是参考重复或被跨款共用——先花 0 元查清楚比事后重出便宜。

## 一条命令

```bash
# 读素材盘（默认 \\192.168.2.19\...\2-种草视频\素材\<款号>\<组号>\）
python scripts/ref_audit.py --sku KF96103773

# 读项目本地 01_素材库
python scripts/ref_audit.py --sku KF96467710 --local

# 更严：有 WARN 也返回 1；再额外留档一份到 06_处理日志
python scripts/ref_audit.py --sku KF96103773 --strict --archive
```

- **动作画像自动找环境**：不传 `--pose-python` 时依次试 `<项目>/.venv`、当前解释器；不传 `--pose-model` 时找 `<项目>/models/pose_landmarker_lite.task`。都探测不到就降级成「只查参考重复」，报告里 `pose_checked=false` 并给 `POSE_SKIPPED` 警告——**这意味着动作类型没查**，正式交片前要补装。
- 退出码：`0` 继续；`1` 有 BLOCK（`--strict` 时 WARN 也算）。
- 结果固定写 `_check/<款号>/ref_audit/`：`report.json`（机器读）、`gate.json`（闸门最近一次判定）、`四条参考_1fps拼版.jpg`（人眼读）。**别改这个路径**，`submit.py` 只认它。

## 查什么

| 层 | 指标 | 做法 | 判据 |
|---|---|---|---|
| 字节 | MD5 / 大小 / 分辨率 / 时长 / 音频采样率 | 直接算 | 同一 MD5 = 同一文件 |
| 内容 | 两两最小 MAE | 2 fps 抽帧 → 64×64 灰度 → ±4 s 滑窗对齐 | **<8 同一段**；8–10 存疑；>10 不同 |
| 动作 | 净位移（肩宽）、抬手占比、最大抬升（体长） | mediapipe 5 fps，阈值全部按体长/肩宽归一化 | 位移 ≥0.30 = 走动；抬手占比 ≥8% = 有抬手 |
| 动作种类 | `走动 / 走动+抬手 / 站定摆拍 / 站定+抬手` | 上面两项组合 | 组数 ≥3 而种类 ≤2 = 类型贫瘠 |
| 跨款 | 本条参考的 MD5 是否被别的款用 | 扫整个素材根目录（带 mtime 缓存） | 命中 = 跨款共用，成片必然趋同 |
| 图片 | 场景参考_01 / 反面 / 服装细节 是否跨组同 MD5 | 直接算 | 反面同 MD5 = 同一张当各组背面 |

## 输出怎么读

控制台是纯 ASCII（Windows 终端不乱码），中文细节在 `report.json`。

| code | 级别 | 含义 | 怎么办 |
|---|---|---|---|
| `REF_IDENTICAL` | BLOCK | 动作参考字节完全相同 | 换参考，别在同一条上出多组 |
| `REF_SAME_CONTENT` | BLOCK | 不同 MD5 但是同一段（改封装/裁剪） | 同上 |
| `REF_MISSING` / `REF_UNREADABLE` | BLOCK | 缺参考 / 解不开 | 补素材 |
| `BACK_IDENTICAL` | WARN | 反面图跨组同一张 | 目视确认是不是这件衣服；不是就让上游补 |
| `REF_SHARED_ACROSS_SKU` | WARN | 这条参考别的款也在用 | 记录在案；批量出片必然同质化 |
| `REF_LOW_VARIETY` | WARN | 组数≥3 但动作只有 ≤2 类 | 窗口/提示词补事件，或要求补拍 |
| `REF_FLAT` | WARN | 位移 <0.15 肩宽且手部最大抬升 <0.10 体长 | 该组最容易被模型自己加戏成抬手比耶 |
| `MIXED_SPEC` | WARN | 分辨率/音频采样率不一致 | 切片前统一，免得平台二次处理 |
| `FLAT_SHARED` | INFO | 服装细节共用平铺图 | 正常 |
| `POSE_SKIPPED` | WARN | 没装 mediapipe / 没找到姿态模型，动作类型没查 | `init_project.py --venv --install` 后重跑 |

## 闸门怎么拦（submit.py 的三种 exit 3）

| 情况 | 控制台会说什么 | 怎么修 |
|---|---|---|
| 报告不存在 | `no reference audit report` | 按第 2 步跑 ref_audit.py |
| 有 BLOCK | `ref audit has N BLOCK item(s): REF_SAME_CONTENTx6, ...` | 换参考后重跑；BLOCK 项中文原文在 `_check/<款号>/ref_audit/gate.json` |
| 报告过期 | `ref audit report is stale: materials changed after it` | 素材动过就重跑，别拿旧报告糊弄 |

唯一放行方式：`--ignore-ref-audit "<主管原话>"`。原话、被拦项、时间一起写进：

- `_check/<款号>/approvals/<版本>_stage_<a|b>_approval.json` 的 `ref_audit_gate` 字段
- `_check/<款号>/ref_audit/gate.json`

事后任何一次审计都能看出「这一版是硬过的」。**不要为了跑通去改 submit.py，也不要删 report.json——删了只会报「没跑体检」。**

## 让 AI 判：把 report.json 丢进去，固定问这 6 句

```
你是视频生成流水线的质检。下面是某款号的参考体检 report.json，只看证据下结论，不要猜。

1. 这一款的动作参考里，有没有"同一段内容"被当成多组在用？给 code 和组号。
2. 有多少条参考被别的款共用？列出"本条组号 → 被哪些款用过"。
3. 动作类型一共几种？哪几组是同一类？如果只有 ≤2 类，指出这意味着什么。
4. 哪几组参考"动作贫瘠"？给出 net_travel 与 arm_up_max 两个数字。
5. 图片层面有没有硬伤（反面图跨组同一张）？
6. 只给能落地的修法，每条注明：改素材 / 改窗口 / 改提示词 / 必须重拍，以及是否要花钱重出。

输出一张表：组号 | 问题 code | 证据数字 | 修法 | 花钱?
最后一行给结论：这批料能不能直接提交（能 / 不能 / 有条件能）。
```

## 阈值怎么来的

- MAE 8 / 10：在 KF96103773（4 段独立拍摄，实测 51–70）、KF96467710、WF96455282 上标定；同一条改封装的片子实测 MAE 通常 <2，取 8 留余量。
- `net_travel 0.30`：走动镜头净位移普遍 >0.3 肩宽，站定摆姿 <0.1。
- `raise 0.10 体长`：手抬到肩以上 10% 体长才算"抬手"；只到肩高（0.0–0.1）容易和自然摆臂混淆。
- `REF_FLAT` 的 `arm_up_max < 0.10`：实测 G1 这类"手只到肩"的素材 max 在 0.2 左右也会被判贫瘠，所以判据是"位移 + 抬手占比"双低，不是单看 max。

## 已知边界（别当万灵药）

1. **动作画像只是粗分**：只分走动/站定、抬手/不抬手，不认"转圈""比耶"这类具体手势。要认具体手势得另做分类器。
2. **浅色小动作素材上骨架会飘**（项目里踩过）：手臂折三角、头身分离时 `net_travel` 会失真，所以阈值给了较宽的 0.30。
3. **只查参考，不查成片**：成片是否复刻了参考，要用姿态 DTW 比（`tools/pose_dtw_compare.py`）。本条工具回答的是"料有没有问题"，不是"片子有没有跑偏"。
4. 跨款扫描读的是整个素材根目录，第一次跑网络盘会慢（~300 MB），之后走 `_check/_ref_hash_cache.json` 缓存。
