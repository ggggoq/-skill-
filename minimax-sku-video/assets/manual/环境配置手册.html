环境配置手册
从零到能跑，只做这些

这份手册只负责一件事：把图生视频的运行环境装好，跑到自检全绿。装完就可以交给主管开始接款。 接款、生成、质检是另一套流程，不在本手册范围内。

每一步都能让 WorkBuddy 代办。 每步都有一个黑色提示词块，整段复制发给 WorkBuddy，它就会代为执行那一步。 提示词里 【方括号】 标的是要你替换成真实信息的地方（路径、密钥、报错原文）。 ffmpeg 已经随技能包带来（tools\ffmpeg.exe），不用你找。只有"申请 API Key"这件事它替不了你——其余检查、建文件、跑命令、看结果，都能交给它。
只做本手册写的事。 环境没装好之前，不要碰生成、提交、质检那些步骤——那些会花钱， 而且是装好环境之后才用得上的。有任何一步卡住，停下来问主管，不要自己换版本号或找替代方案硬试。

0开工前：先备齐 2 样

要备的东西具体要求怎么确认 / 怎么拿
Python 必须 版本 3.10 – 3.12。不能是 3.13+，也不能低于 3.10（姿态识别库 mediapipe 只支持这个区间）。 命令行跑 python --version，看到 Python 3.10.x ~ 3.12.x 即可。装 Python 时记得勾选 Add Python to PATH。
ffmpeg.exe 包内已带 视频裁切、时长探测、音轨处理都靠它。技能包里已附带，不用你准备。 就在技能目录的 tools\ffmpeg.exe。第 3 步命令会用它，照抄即可，不用自己下载或编译。
AIMAXHUG API Key 必须 一串调用视频生成接口的密钥。等同账号钥匙，不要发给别人、不要贴进群。 向主管申请。拿到后按第 2 步写进项目里。新人不用自己注册账号或充值。
对 WorkBuddy 说这句 · 环境体检
帮我体检这台电脑跑图生视频的环境，只检查、别改东西，逐项报告"就绪"还是"缺"：
1. Python 版本是否在 3.10–3.12（用 python --version 查）；
2. 有没有可用的 ffmpeg（命令行 ffmpeg -version 或常见路径都查一下）；
3. AIMAXHUG API Key 是否已在环境变量或已有配置文件里配好。
缺的告诉我具体怎么补。查 Key 时只说"已配置/未配置"，不要打印完整密钥。

1装好技能脚本

整套脚本随 minimax-sku-video 技能一起交付，装在 WorkBuddy 的用户技能目录里：

%USERPROFILE%\.workbuddy\skills\minimax-sku-video\

确认里面有 scripts\init_project.py 这个文件。后面所有命令都要在这个技能目录下执行—— 先打开命令行，切到这个目录：

cd /d "%USERPROFILE%\.workbuddy\skills\minimax-sku-video"

如果技能目录不在这台机器上，先让主管把技能包装上，再继续。不要从网上随便找脚本替代。

对 WorkBuddy 说这句 · 确认技能装好
帮我确认 minimax-sku-video 技能装好没有：找到它的 scripts/init_project.py 文件，
把技能的绝对路径告诉我。找不到就直说"未安装"，别猜路径、也别去网上找替代品。

2把 API Key 放进项目

先想好项目要建在哪个目录，例如 D:/视频项目（一个空目录即可，不用自己建子目录，脚本会自动建）。 把主管给的 Key 写进这个目录的 .env 文件：

AIMAXHUG_API_KEY=把你拿到的密钥粘贴在这里

文件名就是 .env（前面有个点），放在项目根目录，和脚本目录不是一回事。 等号后面不要加引号、不要留空格。装环境时脚本会自动读这个文件。

常见坑：把 Key 写进了技能目录的 .env.example 模板——那是示例文件，不生效。 要写的是你自己项目根目录下新建的 .env。
对 WorkBuddy 说这句 · 写入 API Key
我要在【项目目录，例如 D:/视频项目】建项目。帮我在此目录新建 .env 文件（已有就追加），写入一行：
AIMAXHUG_API_KEY=【把主管给的密钥粘贴到这里，等号后不加引号、不留空格】

写完读回文件确认格式正确，回复里只显示密钥前 6 位和后 4 位，不要显示完整密钥。
如果这台机器已装 aimaxhug-generation 且配过同款 Key，也可以直接帮你复用——先检查再告诉我，别重复写入。

3一键装环境

在技能目录下，跑这一条命令（只把项目目录换成你自己的，ffmpeg 用包内自带的路径，照抄即可）：

python scripts/init_project.py --root "D:/视频项目" --venv --install --ffmpeg "tools/ffmpeg.exe"
参数作用
--root "D:/视频项目"项目建在哪。换成你要放项目的目录。
--venv --install建独立虚拟环境并把依赖库全装上。不要省，否则后面脚本跑不起来。
--ffmpeg "tools/ffmpeg.exe"指向技能包自带的 ffmpeg（在技能目录下执行，所以路径就是 tools/ffmpeg.exe）。脚本会自动复制进项目并配好。

这条命令会自动做 5 件事，你不用手动干预：

  • 建好全部项目目录（素材库 / 待审核 / 历史版本 / 配置等）
  • 把引擎代码装进项目的 src/ 和 tools/
  • 写好依赖清单、项目说明和标记文件
  • 把 ffmpeg 复制进项目并配置路径
  • 下载姿态识别模型到 models/，并安装全部 Python 依赖

装依赖这一步可能要 1–3 分钟，屏幕不动是正常的，等它跑完。整个过程需要联网。

4看自检结果：5 项全 OK 才算装好

命令跑完会打印一段 === 自检 ===。逐项对照：

检查项应该看到没过怎么办
目录齐缺目录说明项目路径没写对，重跑第 3 步。
引擎每个文件后都是 OK出现「缺」= 技能包不完整，找主管重装技能。

对 WorkBuddy 说这句 · 判读自检

5最后一步：验证虚拟环境可用

依赖都装在项目的 .venv 里。给人看的做法是先激活：

cd /d "D:/视频项目"
.venv\Scripts\activate

激活成功后，命令行前面会出现 (.venv)。看到它，就说明环境彻底就绪了。

但交给 WorkBuddy 代办时不能用这招。 它每执行一条命令都是独立新进程， activate 的激活状态留不住。所以给 WorkBuddy 的提示词里改用 .venv\Scripts\python.exe 全路径调用——每次都点名这个解释器，比激活更稳。

这一步只是"开工时切换环境"，不算安装的一部分。今天装完到这里就可以收工， 明天正式接款前再验证一次即可。怎么接款、怎么生成视频——见技能的 references/pipeline.md。

对 WorkBuddy 说这句 · 验证虚拟环境（代理专用写法）
帮我验证项目的虚拟环境是否可用：用【项目目录】/.venv/Scripts/python.exe --version 确认能跑通。
注意别依赖 activate——你每执行一条命令都是独立进程，激活状态留不住。
以后让我跑这个项目的任何 python 脚本，一律用这个 .venv 的 python.exe 全路径执行。
